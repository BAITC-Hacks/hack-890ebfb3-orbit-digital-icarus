## Defects found and corrected during review

- **Stale offer acceptance:** editing a listing or replacing an invitation previously retained the old event revision. The review reproduced an old acceptance approving a changed offer. Both actions now advance the revision; stale responses/plan saves return 409. Unrelated accepted roles remain current, while the affected offer requires a fresh acceptance. Tests also verify that recipients see the current price and description.
- **Non-finite insights errors:** the mounted date-comparison app initially lacked the core JSON-safe validation handler. Three regressions first reproduced HTTP 500 for NaN/infinities, then passed with HTTP 422 after reusing the shared handler.
- **Provider price typing:** sequential `4e2` must not be silently converted to `42`. The listing editor now preserves rejected-edit state until an intentional correction, while an empty draft accepts a new valid digit. Price bounds, grouped values, paste, selection and mobile-style edits have regression coverage.
- **Theme/accessibility:** shared light/dark tokens fix earlier low-contrast hints/evidence. Header icons are centered SVGs; primary controls and interactive links have comfortable targets. Native optional working-language selection and the snapshot/date notice are retained when adapting Spectra's new layout.
- **Test-only corrections:** a component test tried to click New listing before templates enabled it; it now waits for readiness. A browser assertion incorrectly expected Send to be enabled for an empty chat draft; it now checks an enabled editor and disabled empty-message submission. Neither test was fixed by weakening application safeguards.
